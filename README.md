# 医院门诊管理系统（Hospital Outpatient System）

对标小型 HIS 门诊业务的医院门诊管理系统 Web 后台，课程设计项目。

**功能模块**：患者档案、当日挂号、预约挂号（提前预约/取号/取消）、医生排班、处方开具、门诊病历（含检验开单）、医生接诊/完成就诊、药房发药、收费退费、检验计费、检验结果录入与汇总、体征记录、诊断管理、用户管理、科室管理、公告管理、编码参考、患者自助查询（就诊记录/缴费记录/检验报告单）、报表查询。

**技术栈**：Python Flask + MySQL 8.4 + 黑盒测试（禅道用例）+ XMind 需求设计

## 功能总览

| 模块 | 说明 |
| --- | --- |
| 患者档案管理 | 建档、查询、修改、删除；病历号/身份证/电话唯一约束 |
| 挂号管理 | 按排班挂号、自动收取挂号费、排队号、退号恢复号源 |
| 预约挂号 | 提前预约未来排班，生成预约流水号与挂号时限，就诊当日取号转正式挂号，逾期作废释放号源 |

| 医生排班 | 号源管理、停诊保护（有挂号的排班禁止停诊） |
| 处方开具 | 多药品明细、库存校验、金额自动计算、完整状态机 |
| 诊断管理 | 医生添加/修改患者诊断结果，随病历闭环 |
| 门诊病历 | 按「一次就诊」一份病历书写（主诉/现病史/既往史/体格检查/诊断/医嘱），关联挂号与患者档案；同一表单内可直接勾选检验项目开具申请；医生仅能书写与查看自己接诊的病历，管理员可查看全部；支持草稿/归档、关键词检索与 A4 打印 |

| 检验管理 | 检验申请（按项目单价自动计费）、结果录入、状态自动流转（待检验→检验中→已完成）、按患者汇总、异常统计 |

| 用户管理 | 超级用户注册挂号员/医生/收费员/检验技师/药房人员账号，医生自动建档；重置密码、启用/锁定账号、删除 |
| 科室管理 | 科室新增与修改，科室编码唯一 |
| 公告管理 | 仅管理员可发布/删除公告，首页展示最新公告 |
| 编码参考 | 集中查看科室、角色、药品、检验项目等基础字典 |
| 报表查询 | 今日挂号统计、收费日报、处方明细、医生工作量、CSV 导出 |

## 快速运行

```bash
# 1. 启动 MySQL（免服务方式）
start_mysql.bat

# 2. 初始化数据库（一键执行 sql/01~11，可重复运行）
python init_database.py

# 3. 启动 Web
run_web.bat   # 或 cd web_app && python app.py
# 浏览器打开 http://127.0.0.1:5000
```

## 部署到公网（免费）

项目已适配 **腾讯云 EdgeOne Makers**（原 EdgeOne Pages，Python 云函数，原生支持 Flask 框架），
配合免费云 MySQL 即可让任何人通过网址访问，**数据库的存储过程与触发器原样保留**。

```bash
# 1. 把数据库导到云端（首次运行会引导填写连接信息，存入 my_cloud_db.cnf）
python deploy_cloud_db.py           # 或双击 deploy_cloud_db.bat

# 2. 同步云函数目录（改过 web_app/ 代码后必跑）
python build_edgeone.py

# 3. 推送，EdgeOne 自动构建部署
git add . && git commit -m "更新" && git push
```

之后在 EdgeOne Makers 控制台（console.tencentcloud.com/edgeone）导入本仓库即可自动构建部署。

> 注：平台免费分配的 `xxx.edgeone.site` 项目域名在中国大陆访问时**只提供 3 小时有效的
> 预览链接**（超时返回 401），想让链接长期可用需绑定自己的域名。详见部署文档第八之二节。

完整步骤（免费 MySQL 创建、SQL 导入、环境变量配置、报错排查）见
**[docs/部署到公网_EdgeOne.md](docs/部署到公网_EdgeOne.md)**。

> ⚠️ 上面的流程解决的是「**怎么把系统跑起来、拿到一个能演示的网址**」。

## 数据库设计要点

- **表**：19 张（含检验项目字典、检验申请单、检验结果明细、患者体征记录、预约挂号表、公告表、门诊病历表）
- **视图**：9 个（检验单列表含费用与收费状态、检验结果明细、按患者检验汇总、体征历史等）
- **存储过程**：18 个（全部使用事务：挂号、退号、收费退费、发药、检验开单/收费/录结果、体征、用户注册、预约创建/取消/取号、病历号生成与病历保存等）
- **触发器**：4 个（挂号/收费/建档自动写日志、有挂号的排班禁止停诊）
- **约束与索引**：唯一约束、检查约束、高频查询索引

> **关于脚本条数与实际对象数的差异**：在 `sql/` 里直接数 `CREATE` 语句会得到
> 11 条 `CREATE VIEW` 和 20 条 `CREATE PROCEDURE`，比上面的 9 / 18 各多 2 条。
> 原因是后期脚本用 `DROP ... IF EXISTS` + 重新 `CREATE` 的方式**覆盖升级**了早期定义：
>
> | 被覆盖的对象 | 早期定义 | 覆盖升级 | 升级内容 |
> | --- | --- | --- | --- |
> | `v_doctor_schedule` | `03_views.sql` | `10_appointment.sql` | 补预约字段 |
> | `sp_register` | `04_procedures.sql` | `10_appointment.sql` | 支持预约取号 |
> | `v_lab_test_list` | `08_lab_vitals.sql` | `09_task2_gaps.sql` | 补检验单据字段 |
> | `sp_add_lab_test` | `08_lab_vitals.sql` | `09_task2_gaps.sql` | 补业务校验 |
>
> 所以按 `01 → 13` 顺序完整导入后，数据库里的实际对象数是 **9 个视图 / 18 个存储过程**。

## 异常处理与数据一致性

Web 层的写操作统一采用「**三层捕获 + 全局兜底**」，对应 Java 里
`DuplicateKeyException → SQLException → NullPointerException → Exception` 的分层思路：

```python
except mysql.connector.errors.IntegrityError as error:   # ① 唯一键/外键/超长
    flash(handle_integrity_error(error), "error")
except mysql.connector.Error as error:                   # ② 连接/超时/权限/SQL
    flash(handle_db_error(error), "error")
except (KeyError, TypeError, ValueError) as error:       # ③ 必填项缺失（≈ NPE）
    flash(handle_param_error(error), "error")
# ④ 其余异常由 @app.errorhandler(Exception) 兜底，只记日志、不回显异常原文
```

- **顺序不能颠倒**：`IntegrityError` 是 `mysql.connector.Error` 的子类，写反了第一层形同虚设。
- **重复数据能报出具体字段**：1062 报错文本里的 `for key 'users.username'` 会被解析出来，
  经 18 条「索引名 → 中文字段名」映射表转成「登录名已存在，请更换后重试」这类提示，
  而不是笼统的「数据库访问异常」。
- **多步写单事务**：`db.execute_atomic([(sql, params), ...])` 一次提交多条语句，中途失败整体回滚，
  避免「删了一半」的脏数据；目前用于 `delete_user` 的三步关联清理。
- **500 页面不外泄内部信息**：不回显 `type(error).__name__` 与堆栈，堆栈只写日志；
  `/healthz` 另有 `HIS_HEALTH_TOKEN` 闸门控制详情可见性。

现有 17 个**数据写入**路由已全部套用该结构，可直接参照。
（全站共有 18 个 POST 路由，另一个是只读取表单的 `/login`，不需要写入类异常分支。）
