对标小型 HIS 门诊业务的医院门诊管理系统 Web 后台，课程设计项目。

**功能模块**：患者档案、当日挂号、医生排班、医生接诊工作台（左侧步骤条引导：就诊队列→现场体征→问诊→按需检验→开药/完成，含既往就诊史与检验结果内联）、处方开具、门诊病历（含检验开单、检验异常高亮）、药房发药、收费退费、检验计费、检验结果录入与汇总、体征记录、诊断管理、用户管理、科室管理、公告管理、编码参考、报表查询。

**技术栈**：Python Flask + MySQL 8.4 + 黑盒测试（禅道用例）+ XMind 需求设计

## 功能总览

| 模块 | 说明 |
| --- | --- |
| 患者档案管理 | 收费窗口建档、查询、修改、删除；病历号/身份证/电话唯一约束 |
| 挂号管理 | 收费窗口按排班挂号、自动收取挂号费、排队号、退号恢复号源 |
| **智能分诊（挂号辅助）** | 在挂号页输入症状描述，用**文本向量化 + 余弦相似度**算出与 8 个科室的匹配度并给出 Top3；每条结果解释「命中了哪几个症状词」，点击推荐科室即可筛选当日排班。输出的是**科室匹配度，不是疾病概率**，最终以医生判断为准（实现见 `web_app/triage.py`） |
| 医生排班 | 号源管理、停诊保护（有挂号的排班禁止停诊） |
| 处方开具 | 多药品明细、库存校验、金额自动计算、完整状态机 |
| 诊断管理 | **医生**与管理员均可添加/修改患者档案的最近诊断结果，随病历闭环（任务书「诊断功能」要求医生可维护诊断） |
| 医生接诊工作台 | **左侧竖排步骤条 + 右侧单步内容**的引导式问诊闭环：**今日队列 → 开始接诊（待就诊→就诊中）→ 左侧第 1 步问诊·写病历（现场测体征 + 主诉/现病史/体格检查/诊断/医嘱）→ 第 2 步按需开具检验（可展开看逐项结果，不需检验可跳过）→ 第 3 步开药 → 第 4 步完成就诊（→已就诊）**；点左侧步骤或「保存并去开检验 / 跳过，去开药 / 不开药，去完成就诊」按钮逐步推进，页面一次只显示当前步；完成就诊前强制要求已书写病历；左侧可折叠查看该患者**既往就诊史**（历次诊断/病历）与近 3 次体征；医生只看/只操作本人名下挂号，体征的患者与挂号一律取接诊上下文（不采信表单），管理员可查看队列与工作区 |
| 门诊病历 | 按「一次就诊」一份病历书写（主诉/现病史/既往史/体格检查/诊断/医嘱），关联挂号与患者档案；同一表单内可直接勾选检验项目开具申请；医生仅能书写与查看自己接诊的病历，管理员可查看全部；支持草稿/归档、关键词检索与 A4 打印；**打印页把检验科结果逐项列出，异常项（偏高/偏低/异常）加粗标红并给出「检出 N 项异常指标」提示** |
| 体征记录 | 医生录入体温/血压/心率等体征，形成体征历史；接诊工作台第 1 步内联同一能力（与本次就诊绑定），本页仍可用于独立补录 |
| 检验管理 | 检验申请（按项目单价自动计费）、结果录入、状态自动流转（待检验→检验中→已完成）、按患者汇总、异常统计 |
| 药房发药 | 已收费处方复核库存后发药，处方状态：待收费→已收费→已发药 |
| 收费退费 | 处方收费扣库存、退费恢复库存、检验单收费（检查费）、防重复收费 |
| 用户管理 | 超级用户注册收费人员/医生/检验科人员/药房人员账号，医生自动建档；重置密码、启用/锁定账号、删除 |
| 科室管理 | 科室新增与修改，科室编码唯一 |
| 公告管理 | 仅管理员可发布/删除公告，首页展示最新公告 |
| 编码参考 | 集中查看科室、角色、药品、检验项目等基础字典 |
| 报表查询 | 今日挂号统计、收费日报、处方明细、医生工作量、CSV 导出 |

## 自动化测试

`tests/` 下有一套 **215 个用例**的自动化测试，只用 Python 标准库 `unittest`，
不引入任何额外依赖：

```bash
python -m unittest discover -s tests -v   # 或双击 run_tests.bat
```

分三类，互不干扰：

- **离线静态契约（38 个）**：不碰数据库，克隆下来就能跑。把路由/模板清单、
  三层异常分层的覆盖数量、Jinja `.items` 陷阱、密码哈希格式、检验结果标志判定、
  业务单号唯一性等「接口契约」写成断言——改动接口时会立刻失败，逼迫改动显式化。
- **离线分诊算法（28 个）**：同样不碰数据库。64 条明确病例断言 Top1 命中科室，
  10 条模糊主诉断言命中 Top3，另含归一化、双向最大匹配、跨词边界假词回归、
  余弦相似度性质与结果结构校验。
- **业务集成（134 个）**：走 Flask 测试客户端跑真实 HTTP 处理链路，直连本地 MySQL，
  覆盖建档 → 挂号 → 接诊 → 病历 → 检验 → 处方 → 收费 → 发药的全流程，
  以及五角色权限矩阵、字典维护、报表导出。
  数据库不可用时这些用例会**优雅跳过**而不是报错。

用例之间互不污染、可反复运行：所有业务数据都挂在测试自建的患者/医生名下，
`tearDown` 按外键依赖顺序反查清理，之后数据库对象数与基线完全一致。

> 详细说明、接口契约清单与「测试抓到过的真实缺陷」见 **[`tests/README.md`](tests/README.md)**。
>
> 例如：`make_no()` 早期用秒级时间戳，同一秒连续两次挂号会撞 `reg_no` 唯一索引；
> `sp_issue_prescription` 曾把 `doctors.doctor_id` 当成 `users.user_id` 写审计日志，
> 导致部分医生**每次开方都因外键 1452 回滚失败**。两处均已修复并加了回归守卫。

## 数据库设计要点

## 异常处理与数据一致性

Web 层的写操作统一采用「**三层捕获 + 全局兜底**」，对应 Java 里
`DuplicateKeyException → SQLException → NullPointerException → Exception` 的分层思路：

```python
except mysql.connector.errors.IntegrityError as error:   # ① 唯一键/外键/超长
    flash(handle_integrity_error(error), "error")
except mysql.connector.Error as error:                   # ② 连接/超时/权限/SQL
    flash(handle_db_error(error), "error")
except (KeyError, TypeError, ValueError) as error:       # ③ 必填项缺失（≈ NPE）
    flash(handle_param_error(error), "error")
# ④ 其余异常由 @app.errorhandler(Exception) 兜底，只记日志、不回显异常原文
```

- **顺序不能颠倒**：`IntegrityError` 是 `mysql.connector.Error` 的子类，写反了第一层形同虚设。
- **重复数据能报出具体字段**：1062 报错文本里的 `for key 'users.username'` 会被解析出来，
  经 18 条「索引名 → 中文字段名」映射表转成「登录名已存在，请更换后重试」这类提示，
  而不是笼统的「数据库访问异常」。
- **多步写单事务**：`db.execute_atomic([(sql, params), ...])` 一次提交多条语句，中途失败整体回滚，
  避免「删了一半」的脏数据；目前用于 `delete_user` 的三步关联清理。
- **500 页面不外泄内部信息**：不回显 `type(error).__name__` 与堆栈，堆栈只写日志；
  `/healthz` 另有 `HIS_HEALTH_TOKEN` 闸门控制详情可见性。

现有 18 个**数据写入**路由已全部套用该结构，可直接参照。
（全站共有 20 个含 POST 的端点，另外两个不需要写入类异常分支：只读取表单的 `/login`，
以及纯向量计算、完全不碰数据库的 `/api/triage`。）

## 安全加固

代码审查后补齐的一层防护，均可在环境变量里开关：

| 机制 | 说明 | 相关环境变量 |
| --- | --- | --- |
| CSRF | 所有表单 POST 必须带会话内签发的 token（`base.html` 统一注入 hidden 字段）；`/api/mini/*` 走 JSON，不受此限 | `HIS_CSRF=0` 可关闭（默认开） |
| 会话密钥 | 优先用环境变量，否则首次启动生成 `.his_secret_key` 并落盘（重启不掉登录）；文件只读时才回退内置值 | `HIS_SECRET_KEY`、`HIS_SECRET_FILE` |
| 会话 cookie | `HttpOnly` + `SameSite=Lax`；HTTPS 部署时设 `HIS_COOKIE_SECURE=1` 加上 `Secure` | `HIS_COOKIE_SECURE` |
| 账号撤权 | 每个会话最多 60 秒复核一次账号状态，锁定/删除后立即踢出 | — |
| 登录限流 | 同一 IP + 账号 5 次失败锁 10 分钟 | — |
| 密码强度 | 长度 6~64 位（新增账号、重置密码都校验） | — |
| 数据库报错 | 默认不回显 MySQL 原文（含表名/列名），只写服务端日志 | `HIS_SHOW_SQL_ERROR=1` 可回显 |
| CSV 导出 | 以 `= + - @` 开头的单元格加前导单引号，防 Excel 公式注入 | — |
| 响应头 | `X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、`Referrer-Policy` | — |
| 小程序 API | 每 IP 每分钟 60 次限流；退号必须带匹配的 `id_card`；挂号幂等（同患者同医生当天只一条）；手机号脱敏 | `HIS_MINI_OPERATOR_ID` |
| 自检页 | 配了 `HIS_HEALTH_TOKEN` 时须带 token；未配时仅本机可看详情，外部只回 `OK` | `HIS_HEALTH_TOKEN` |

> ⚠️ 首次启动会生成 `.his_secret_key`（已加入 `.gitignore`），因此**旧会话会全部失效一次**，重新登录即可。
> 调试模式默认关闭；开启调试器（`HIS_WEB_DEBUG=1`）时请只监听 `127.0.0.1`。
