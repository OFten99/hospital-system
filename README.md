# 医院门诊管理系统

本项目是一套面向小型医院门诊业务的 Web 后台，覆盖患者建档、挂号、接诊、检验、处方、收费、发药到报表的完整流程。
后端 Python Flask，数据落在 MySQL 8，挂号页附带一个纯标准库实现的症状分诊模块。

## 功能

| 模块 | 说明 |
| --- | --- |
| 患者档案 | 收费窗口建档、查询、修改、删除；病历号、身份证、电话唯一约束 |
| 挂号 | 按排班挂号并自动收挂号费、生成排队号；退号恢复号源 |
| 智能分诊 | 挂号页输入症状描述，按与 8 个科室的匹配度给出 Top3，并解释命中的症状词。输出的是科室匹配度而非疾病概率，最终以医生判断为准 |
| 医生排班 | 号源管理；有挂号的排班禁止停诊 |
| 接诊工作台 | 左侧步骤条引导：今日队列 → 问诊写病历（含现场体征）→ 按需开检验 → 开药 → 完成就诊。可折叠查看患者既往就诊史与近三次体征 |
| 门诊病历 | 一次就诊一份病历（主诉、现病史、既往史、体格检查、诊断、医嘱），可同页勾选检验项目；支持草稿/归档、检索与 A4 打印，打印页列出检验结果并高亮异常项 |
| 处方 | 多药品明细、库存校验、金额自动计算，状态机为待收费 → 已收费 → 已发药 |
| 收费退费 | 处方与检验单收费、退费恢复库存、防重复收费 |
| 药房发药 | 已收费处方复核库存后发药 |
| 检验 | 申请按时开单、结果录入、状态自动流转、按患者汇总与异常统计 |
| 体征记录 | 体温、血压、心率等，形成体征历史，接诊时与本次就诊绑定 |
| 诊断管理 | 医生与管理员可维护患者最近诊断，随病历闭环 |
| 用户与科室 | 超级用户注册各岗位账号（医生自动建档）、重置密码、启用锁定；科室编码唯一 |
| 公告与字典 | 管理员发布公告；集中查看科室、角色、药品、检验项目等基础字典 |
| 报表 | 今日挂号、收费日报、处方明细、医生工作量，支持 CSV 导出 |

## 运行

需要 Python 3.8 以上和本地 MySQL 8。

```bash
start_mysql.bat                              # 1. 免服务方式拉起 MySQL
python scripts/init_database.py              # 2. 建库并依次执行 sql/01~15，可重复运行
run_web.bat                                  # 3. 启动，浏览器打开 http://127.0.0.1:5000
```

`run_web.bat` 会自动找 Python、装依赖、检查 MySQL 是否在跑。其余命令：

```bash
python -m unittest discover -s tests -v      # 自动化测试，或双击 run_tests.bat
python scripts/demo_prep.py                  # 补当天排班并打印演示清单，或双击 demo_prep.bat
```

挂号页只查当天排班，空库直接演示会卡住，所以我留了 `demo_prep`，跑一次就能把当天的号源补齐。
更细的排错说明见 [运行说明.md](运行说明.md)。

## 分诊模块

`web_app/triage.py` 不依赖任何第三方库。做法是把症状描述和科室画像放进同一个词表空间：
科室画像由人工设定的关键词权重构成，文本归一化后取余弦相似度，取 Top3 作为推荐。

之所以不用 word2vec 一类的模型，是因为训练所需语料规模远超本机条件，手工编码在这个体量下
反而可控、可解释、可评测。

实际跑下来暴露过三个问题，都是我自己踩出来的，v2 里逐个修的：

- 否定句误判。"不发烧也不咳嗽，就是头晕" 曾把发热、咳嗽当作主症状并给出 58% 置信度。
  现在归一化阶段保留标点作为作用域屏障，否定词只向后作用到屏障为止，被否定的症状从打分中剔除并单独回传。
- 急症缺少拦截。"胸口疼 出冷汗 喘不上气" 曾输出内科 45%。现在急症规则走在打分之前，命中即返回急诊指引，不给科室排名。
- 主体错位。"我妈发烧三天了" 曾按说话人本人处理，年龄分流失效。现在识别家属代述并提示确认就诊人。

评测集在 `eval/triage_eval_set.csv`，165 条独立于单元测试，含急症 18 条，`scripts/eval_triage.py` 可复现指标。

## 异常与一致性

写操作统一走三层捕获加全局兜底，顺序不能颠倒，因为 `IntegrityError` 是 `mysql.connector.Error` 的子类：

```python
except mysql.connector.errors.IntegrityError as error:   # 唯一键/外键/超长
    flash(handle_integrity_error(error), "error")
except mysql.connector.Error as error:                   # 连接/超时/权限/SQL
    flash(handle_db_error(error), "error")
except (KeyError, TypeError, ValueError) as error:       # 必填项缺失
    flash(handle_param_error(error), "error")
# 其余异常由 @app.errorhandler(Exception) 兜底，只记日志
```

1062 报错里的 `for key 'users.username'` 会被解析出来，经索引名到中文字段的映射转成
"登录名已存在"这类提示，而不是笼统的数据库异常。多步写用 `db.execute_atomic()` 一次提交，失败整体回滚。
500 页面不回显异常类型与堆栈，只写日志。

## 安全

| 机制 | 说明 |
| --- | --- |
| CSRF | 所有表单 POST 带会话内签发的 token，`HIS_CSRF=0` 可关 |
| 会话密钥 | 优先取环境变量，否则首次启动生成 `.his_secret_key` 落盘 |
| Cookie | `HttpOnly`、`SameSite=Lax`，HTTPS 下可开 `Secure` |
| 撤权 | 会话每 60 秒复核账号状态，锁定或删除后立即踢出 |
| 登录限流 | 同一 IP 加账号 5 次失败锁 10 分钟 |
| 数据库报错 | 默认不回显 MySQL 原文，`HIS_SHOW_SQL_ERROR=1` 可回显 |
| CSV 导出 | 以 `= + - @` 开头的单元格加前导单引号，防公式注入 |
| 响应头 | `X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、`Referrer-Policy` |
| 小程序接口 | 每 IP 每分钟 60 次限流，退号校验 id_card，挂号幂等，手机号脱敏 |

首次启动会生成 `.his_secret_key`（已忽略），旧会话会失效一次，重新登录即可。调试模式默认关闭。

## 测试

`tests/` 下 215 个用例，只用标准库 `unittest`，不引入额外依赖。分三层：

- 离线静态契约 38 个，不碰数据库。把路由与模板清单、异常分层覆盖数、Jinja 陷阱、
  密码哈希格式、业务单号唯一性写成断言，接口一改就失败。
- 离线分诊算法 28 个。64 条明确病例断言 Top1 命中，10 条模糊主诉断言命中 Top3，
  另含归一化、双向最大匹配、余弦相似度性质等。
- 业务集成 134 个，通过 Flask 测试客户端跑真实 HTTP 链路，覆盖建档到发药全流程、
  五角色权限矩阵、字典维护与报表导出。数据库不可用时优雅跳过。

用例之间互不污染，业务数据都挂在测试自建的患者与医生名下，`tearDown` 按外键顺序反查清理，
跑完数据库对象数与基线一致。测试抓到过的真实缺陷记在 [tests/README.md](tests/README.md)，
例如 `make_no()` 早期用秒级时间戳，同一秒两次挂号会撞唯一索引；
`sp_issue_prescription` 曾把 `doctors.doctor_id` 当成 `users.user_id` 写审计日志，导致部分医生开方必然回滚。

黑盒用例是我按禅道的导入模板写的，50 条，放在 `docs/测试/`，禅道导入格式，CSV 为 GBK 编码，Excel 直接打开不乱码。

## 数据库设计

19 张表，9 个视图，18 个存储过程，4 个触发器。

- 表包含检验项目字典、检验申请与结果明细、患者体征、公告、门诊病历。`appointments` 是早期做预约时留下的表，
  预约功能已下线，表内无数据。
- 视图覆盖检验单与收费状态、检验结果明细、按患者汇总、体征历史等。`v_today_registrations` 与
  `v_daily_payment` 只计有效记录，退号退费不计入收入，净收入等于收费减退费。
- 存储过程全部走事务：挂号、退号、收费退费、发药、检验开单收费录结果、体征、
  用户注册、病历号生成与保存。预约相关的创建与取消过程为遗留代码，当前不再调用。
- 触发器 4 个：挂号、收费、建档自动写日志；有挂号的排班禁止停诊。

在 `sql/` 里直接数 CREATE 语句会得到 12 个视图和 23 个存储过程，比实际多 3 和 5，因为后来我改用
`DROP IF EXISTS` 加重建的方式做覆盖升级，早期定义留在脚本里没删。被覆盖的对象：

| 对象 | 早期定义 | 覆盖升级 |
| --- | --- | --- |
| `v_doctor_schedule` | 03_views | 10_appointment，补预约字段 |
| `sp_register` | 04_procedures | 10_appointment 支持预约取号，15 改为当天最大号加一 |
| `v_lab_test_list` | 08_lab_vitals | 09_task2_gaps，补检验单据字段 |
| `sp_add_lab_test` | 08_lab_vitals | 09_task2_gaps，补业务校验 |
| `v_today_registrations` | 03_views | 14_fix_reg_aggregates，退号不计入合计 |
| `sp_charge` | 04_procedures | 15，库存不足报错回滚，原 GREATEST 会静默扣成 0 |
| `sp_record_lab_result` | 08_lab_vitals | 15，已完成检验单不允许改结果 |

按 01 到 15 顺序完整导入后，库里是 9 个视图、18 个存储过程。15 号脚本只做覆盖升级与加索引。
