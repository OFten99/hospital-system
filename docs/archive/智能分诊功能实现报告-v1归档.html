挂号页智能分诊：用向量相似度判断该挂哪个科室

视频那五层本项目的实现诚实评价
① 向量是什么
一串有顺序的数字，高维空间里的一个点		 vectorize() L383：把症状文本变成 {症状词: TF-IDF 分量} 的稀疏向量，146 个维度对应 146 个症状词。 完整实现只用到点积和模长，从不依赖"画得出"的几何直觉。
② 凭什么能表达意思
词义由共现上下文决定		 用手工编码的共现替代训练：每个科室画像就是它的上下文；症状词在哪个科室权重高， 就说明它离哪个科室近。IDF 按"该词出现在几个科室"计算——出现得越少越有区分度。 弱化实现这不是训练出来的 embedding。真正的 word2vec 需要十亿级语料，本项目没有。这一点必须写明，否则就是拿口号骗人。
③ 万物怎么都进来
只要能定义"像不像"，就能训编码器		 为 8 个科室各写一个关键词权重编码器（权重 3/2/1 = 高度特异/中等特异/泛化症状）， 患者输入走同一套同义词表与分词，于是两者可比。 人工编码，非训练好处是每一步可解释、可审计； 代价是要靠人维护知识库，新增科室必须手填关键词。
④ 进来之后能干什么
检索=最近邻，推荐=内积排序		 suggest() L401：对 8 个科室各算一次分数， 排序取 Top3——本质就是最近邻检索。另外 similar_departments() 用同一套向量算科室之间的相似度，用来排查"哪两个科室画像太像、容易分错"。 完整实现聚类与检索两个视角都用上了，没有做 RAG（场景不需要）。
⑤ 哪里是夸张的
有损压缩 / 相似由定义决定 / 高维直觉失效		 三条全部落在实现里：
① 有损压缩：病程、既往史、严重程度全丢，只留"命中哪些词"；
② 相似由定义决定：分数来自我设的权重与阈值，换一套权重排序就会变；
③ 高维直觉失效：阈值不靠感觉，靠样例实测校准。
这三条写进了 triage.py 的模块 docstring，避免以后自己忘。		 主动设限输出是"科室匹配度"， 不是疾病概率、不是诊断。低于阈值时明确让人工导诊介入。

打分公式

分数 = 0.70 × 关键词命中分 + 0.30 × 描述余弦
关键词命中分 = 命中权重和 / (命中权重和 + 2.0)　　← 饱和函数，防止长文本靠堆词取胜
描述余弦 = cos(查询 bigram 向量, 科室描述 bigram 向量)　　← 词表没覆盖的新说法靠它兜底

置信度按 Top1 分数分档：≥0.55 高0.30~0.55 中<0.30 低（提示人工导诊）

七它明确做不到什么

64/64 的准确率不等于泛化能力。这 64 条样例是我在设计知识库时看过并调试过的， 属于训练集内评估。换一批我没见过的说法，准确率一定低于这个数字。 真实系统要靠医院历史挂号数据做独立测试集，本项目没有这个条件。
  • 分不清主诉与伴随症状：如上文牙痛案例，「睡不着」会抢分。要解决需要句法分析或位置加权。
  • 否定句会误判：「没有发烧」「不咳嗽」里的"发热""咳嗽"照样被命中。词袋模型没有否定词处理。
  • 不能处理多科室合并症：「糖尿病足溃烂」同时涉及内科与外科，系统只会给一个排序，不会提示"建议联合门诊"。
  • 知识库要人工维护：新增科室必须手填关键词，否则该科室永远匹配不到。
  • 不是医疗器械：输出是分诊建议，不构成诊断。LICENSE 已写明本项目不可直接用于真实医疗环境。
