# 上线前检查清单（真实生产部署）

> 本文针对的是「**真的挂到公网给外人用**」这个目标，与 `部署到公网_EdgeOne.md` 的定位不同：
> 那份文档解决的是「**怎么把系统跑起来、拿到一个能演示的网址**」（免费演示路径）；
> 本文解决的是「**跑起来之后，能不能让别人随便访问**」。
>
> 图例：🔴 阻断级（不修就是安全漏洞，别上线）｜🟠 重要（公网暴露下迟早出问题）｜🟡 建议（长期持有的技术债）

评测基准（2026-10-02 代码实况）：

- `web_app/app.py` 共 25 个路由，其中 17 个写操作路由已完成三层异常捕获 + 事务化写入。
- 未发现任何 `SESSION_COOKIE_*`、`MAX_CONTENT_LENGTH`、CSRF、限流相关配置。
- `app.secret_key` 存在硬编码回退值 `_DEV_SECRET_FALLBACK`。
- `/healthz` 的令牌闸门默认关闭（`HIS_HEALTH_TOKEN` 未设置时任何人可访问详情页）。

## 一、🔴 阻断级：不修就别挂公网

### 1.1 关掉调试模式

```python
# web_app/app.py 最后一段
app.run(
    host=os.getenv("HIS_WEB_HOST", "127.0.0.1"),
    port=int(os.getenv("HIS_WEB_PORT", "5000")),
    debug=os.getenv("HIS_WEB_DEBUG", "1") == "1",   # ← 默认值是 "1"，即默认开着
)
```

**风险**：`debug=True` 会启用 Werkzeug 交互式调试器。配合 `host=0.0.0.0` 时，任何触发异常的人都能在浏览器里拿到一个 Python 交互式 shell（等于把服务器命令执行权限送出去）。

**说明**：在 EdgeOne Makers 上，平台是以 WSGI 方式 `import` 这个应用，不执行 `if __name__ == "__main__"` 块，所以云端这条路暂时不受影响。但只要你换成「自己开一台云服务器 + `python app.py`」的方式部署，这个默认值就是后门。

**做法**：
- 环境变量显式设 `HIS_WEB_DEBUG=0`；
- 更好的做法是把这个默认值从 `"1"` 改成 `"0"`（默认安全），本地开发时再手动设 `1`。

### 1.2 换掉 SECRET_KEY

```python
_DEV_SECRET_FALLBACK = "hospital-outpatient-his-course-design"
app.secret_key = _ENV_SECRET or _DEV_SECRET_FALLBACK
```

**风险**：Flask 的会话 cookie 是用 `secret_key` 签名的。密钥是硬编码且公开在 GitHub 上，意味着**任何人都能在本地伪造一个 `role=admin` 的会话 cookie**，直接绕过登录拿到管理员权限。这是本项目当前最高危的一项。

**做法**：

```bash
# 生成一个真随机密钥（两个 Python 都能跑）
python -c "import secrets; print(secrets.token_hex(32))"
```

把它设到 `HIS_SECRET_KEY` 环境变量里。改完之后所有已登录用户会被强制登出（签名变了），这是预期行为。

### 1.3 打开自检页令牌

`/healthz` 会回显 `HIS_DB_HOST` / `HIS_DB_PORT` / `HIS_DB_USER` / `HIS_DB_NAME` 以及各环境变量是否还是默认值（密码已打码）。`HIS_HEALTH_TOKEN` 未设置时**该页面完全开放**，等于给扫描器送了一份内网结构说明书。

**做法**：`HIS_HEALTH_TOKEN=$(python -c "import secrets;print(secrets.token_urlsafe(24))")`，之后监控探针用 `/healthz?token=xxx` 访问。

### 1.4 改掉全部默认账号密码

`sql/07_seed_data.sql` 等脚本里预置了 7 个演示账号，密码一律 `123456`：`admin01`、`reg01`、`cash01`、`doctor01`、`lab01`、`pharm01`、`regm01`。

**做法**：演示数据可以保留（方便自测），但**上线实例必须把这 7 个密码逐个改成强密码**；或者干脆不要在生产库里跑 seed 脚本，只建管理员账号。至少 `admin01` 必须是强密码。

## 二、🟠 公网硬化：现在是接近裸奔状态

### 2.1 CSRF 防护（影响面最大的一项）

当前所有写接口都是裸的 `POST` 表单，没有任何 token 校验。攻击者只要在任意页面里放一张 `<img src="https://你的域名/patients/delete?id=1">`，**已登录的医生打开这个页面，数据就被删了**（浏览器会自动带上会话 cookie）。

**做法**：引入 `Flask-WTF` 的 `CSRFProtect`：

```python
from flask_wtf.csrf import CSRFProtect
csrf = CSRFProtect(app)
```

然后在所有 `templates/*.html` 的 `<form method="post">` 里加一行隐藏字段

```html
<input type="hidden" name="csrf_token" value="{{ csrf_token() }}">
```

本项目 22 个模板、17 个写路由，工作量集中在模板侧（可以用脚本批量给所有 POST 表单插一行）。

### 2.2 会话 Cookie 安全属性

```python
app.config.update(
    SESSION_COOKIE_SECURE=True,       # 只走 HTTPS
    SESSION_COOKIE_HTTPONLY=True,     # 禁止 JS 读取
    SESSION_COOKIE_SAMESITE="Lax",    # 缓解跨站请求
    PERMANENT_SESSION_LIFETIME=timedelta(hours=8),
)
```

注意 `SESSION_COOKIE_SECURE=True` 之后，**必须**先配好 HTTPS，否则登录会静默失败（cookie 发不出去）。

### 2.3 登录限流与账号锁定

现在 `login` 路由没有任何次数限制，`123456` 这类弱口令可以无限次暴力尝试。

**做法（由轻到重）**：
- 最轻：给登录失败加计数（`users` 表加 `failed_attempts` / `locked_until` 两列，失败 5 次锁 15 分钟）；
- 次轻：装 `Flask-Limiter`，给 `/login` 挂 `@limiter.limit("10 per minute")`；
- 更省事：如果前面有 Nginx / EdgeOne，直接在网关层按 IP 限速。

### 2.4 请求体大小上限

`MAX_CONTENT_LENGTH` 未设置，意味着有人可以 POST 一个超大表单把内存吃满（云函数会被 OOM 干掉）。

```python
app.config["MAX_CONTENT_LENGTH"] = 2 * 1024 * 1024   # 2 MB，按业务实际需要调
```

### 2.5 安全响应头

至少加上这几个（可以写在 `@app.after_request` 里，不用装扩展）：

```python
@app.after_request
def add_security_headers(resp):
    resp.headers["X-Content-Type-Options"] = "nosniff"
    resp.headers["X-Frame-Options"] = "SAMEORIGIN"
    resp.headers["Referrer-Policy"] = "strict-origin-when-cross-origin"
    return resp
```

### 2.6 已经做好的部分（不用再动）

- ✅ 17 个写路由的三层异常捕获（`IntegrityError` → `mysql.connector.Error` → `KeyError/TypeError/ValueError`）+ 全局 500 兜底；
- ✅ 全局 500 页面不再回显异常类型和异常原文，堆栈只进日志；
- ✅ 多步写入使用 `execute_atomic()` 单事务，失败整体回滚；
- ✅ 密码用 `pbkdf2:sha256` 加盐哈希存储，不是明文。

## 三、🟡 域名与网络：免费的那条路会过期

### 3.1 平台分配的域名在中国大陆只有 3 小时

EdgeOne 官方规则（见 `部署到公网_EdgeOne.md` 第八之二节）：**中国大陆网络环境下，只能用系统生成的预览链接访问，有效期 3 小时，超时返回 401**。也就是说，把 `xxx.edgeone.site` 直接发给别人，3 小时后就是 404/401。

三个选择：

| 方案 | 备案 | 稳定性 | 代价 |
|------|------|--------|------|
| 每次演示前点一次「预览」，当场发链接 | 不需要 | 3 小时内 | 不能长期挂 |
| 绑定自有域名 + 全球可用区（不含中国大陆） | **免备案** | 长期稳定 | 国内访问走海外节点，延迟偏高 |
| 绑定自有域名 + 中国大陆可用区 | **必须完成工信部 ICP 备案** | 长期稳定、速度快 | 备案周期数周 |

如果只是给老师/答辩用，第一条够；如果想做成"长期能访问的地址"，第二条最省事。

### 3.2 HTTPS

绑自有域名时记得申请证书并开启强制 HTTPS 跳转（腾讯云/Cloudflare 都有免费的）。这也是 2.2 节 `SESSION_COOKIE_SECURE` 能生效的前提。

## 四、🟡 数据与运维：出事那天才想起就晚了

### 4.1 绝对不要放真实患者数据

这是**合规红线**，不是技术建议。医疗数据涉及《个人信息保护法》《数据安全法》，患者的姓名、身份证号、病历号属于敏感个人信息，课程设计/演示环境不允许接入真实患者数据。本系统表单里有身份证号、手机号字段，一旦被爬取后果由数据持有者承担。

### 4.2 备份与恢复演练

当前项目**没有任何备份方案**，靠的是 Aiven 或云厂商的默认行为。

- 至少开启 Aiven 控制台的自动备份（免费版也有）；
- 定期（比如每周）用 `mysqldump` 拉一份到本地/对象存储；
- **关键是要演练一次恢复**——没验证过能恢复的备份等于没有备份。

### 4.3 表结构变更要版本化

现在改表结构靠手工执行 `sql/01..11_*.sql`，没有版本记录，团队协作或多环境（本地/云）同步时极易漂移。

**做法**：引入 `Alembic`，把现有 18 张表、9 个视图、16 个存储过程、4 个触发器作为初始迁移导入，之后所有 DDL 走迁移脚本。注意存储过程和触发器需要手写在 migration 的 `op.execute()` 里。

### 4.4 日志留存与操作审计

医院系统的业务要求是**每一个写操作都能追溯到人**。当前系统只有 `app.logger` 输出，没有审计表。

**做法**：加一张 `operation_log` 表（操作人、时间、IP、路由、业务主键、结果），在写路由里统一记一条。这也顺便满足了"异常提示可读 + 行为可追溯"的教学要求。

### 4.5 监控告警

`/healthz` 已经是现成的探针端点，接一个免费的 uptime 监控（如 UptimeRobot）定期打 `https://域名/healthz?token=xxx`，异常时发邮件/微信即可。

### 4.6 托管数据库的免费额度限制

Aiven 免费 MySQL：1 GB 存储、单节点；**实例会休眠/维护重启**，表现为偶发连不上，等几分钟或去控制台重启。免费额度只够演示，如果真有人用，需要升级到付费规格或换正规 RDS。

## 五、⚙️ 架构层面的技术债（量上来才暴露）

- **运行时版本不一致**：EdgeOne Makers 是 Python **3.10**，本机开发是 **3.12**。本地能跑不代表云端能跑，`match` 语句、新模块特性要留意。
- **冷启动延迟**：云函数首次请求有 1~3 秒冷启动，用户体验上要接受。
- **无并发压测**：连接池大小、云函数并发上限都没验证过，建议用 `wrk`/`ab` 跑一轮再定。
- **会话无法主动失效**：session 存在签名 cookie 里，管理员无法"把某个用户踢下线"或"强制所有人重新登录"（除非换 secret key 把所有人一起踢）。要这个能力就必须上服务端 session（Redis）。
- **静态文件**：现在由应用直接返回，量大了应该丢到对象存储 + CDN。
- **单点**：应用和数据库都是单实例，没有冗余。
