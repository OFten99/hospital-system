# 微信小程序「线上挂号」部署与运行说明

线上挂号我另外做了个微信小程序，后端还是复用同一个 Flask 服务、同一套库。
下面是我把它跑起来的全过程：后端接口、小程序前端、本地调试、真机预览。

---

## 一、整体架构

```
微信小程序（miniapp/）
      │  HTTPS / HTTP（JSON API）
      ▼
Flask 后端（web_app/app.py）
      │  新增 /api/mini/* 只读查询 + 挂号提交接口
      ▼
MySQL 8.4（hospital_outpatient 数据库）
      │  复用现有 19 表 / 9 视图 / 18 存储过程 / 4 触发器
      └── sp_register 事务：号源扣减 + 挂号费 + 排队号
```

小程序是 C 端，我只放了下面这几个只读查询加一个挂号提交接口，后台管理还是走浏览器页面。

## 二、后端接口

| 方法 | 路径 | 说明 | 参数 |
|------|------|------|------|
| GET | `/api/mini/departments` | 有医生的科室列表 | — |
| GET | `/api/mini/doctors` | 某科室医生列表 | `department_id` |
| GET | `/api/mini/schedules` | 某医生未来 N 天排班与余号 | `doctor_id`、`days`(默认7) |
| GET | `/api/mini/patient` | 按身份证号查患者 | `id_card` |
| POST | `/api/mini/register` | 线上挂号（自动建档） | JSON，见下 |
| GET | `/api/mini/my_registrations` | 某患者的挂号记录 | `id_card` |
| GET | `/api/mini/search` | 按医生名/科室名模糊搜索医生 | `keyword` |

挂号请求体我是这么定的：

```json
{
  "schedule_id": 421,
  "reg_type": "普通号",
  "pay_method": "微信",
  "patient": {
    "name": "张三",
    "gender": "男",
    "birth_date": "1995-05-05",
    "id_card": "110101199505050011",
    "phone": "13800000000"
  }
}
```

成功返回：

```json
{
  "code": 0,
  "msg": "挂号成功",
  "data": { "reg_no": "REG...", "queue_no": 1, "reg_fee": "50.00" }
}
```

统一返回里 `code` 为 0 表示成功，非 0 会带一句中文 `msg`。

实现上有几点：

- 挂号直接复用 `sp_register` 存储过程，号源扣减、挂号费收取、排队号生成在同一个事务里完成，
  和后台挂号走的是同一条路。
- 患者没建档就自动建档，逻辑和后台 `/patients` 一致。
- 操作员我固定成了收费员 `cash01`（`user_id = 3`，见 `sql/07_seed_data.sql` 第 102 行注释）。
- `work_date` / `reg_date` 用 `DATE_FORMAT` 格式化成 `YYYY-MM-DD` 字符串。

> 这组接口我没做登录鉴权，就是把整个流程跑通用的。真要上线，还得接微信 `openid` 登录和接口签名。

## 三、小程序前端

目录按页面拆的：

```
miniapp/
├── app.json / app.js / app.wxss   # 全局配置、后端地址、全局样式
├── sitemap.json
├── utils/request.js               # 统一请求封装 + 接口调用
└── pages/
    ├── index/      # 首页：搜索框 + 医院头卡 + 双栏（左科室/右医生）+ 就医须知弹窗
    ├── doctors/    # 某科室医生列表（备用，首页双栏已直选医生）
    ├── schedules/  # 医生未来 7 天排班 + 余号选择
    ├── register/   # 填写就诊人信息 + 号别/支付方式 + 提交
    └── mine/       # 我的挂号记录（按身份证号查询）
```

首页我照着真实医院预约小程序的样子做的：顶部搜索框（支持医生名/科室名模糊搜索）+
医院信息卡（名称/等级/地址 + 就诊须知入口）+ 左右双栏（左侧科室分类、右侧该科室可预约医生），
首次进入弹就医须知，点「我知道了」之后不再弹。

关键配置：`app.js` 里的 `globalData.baseUrl` 是后端地址，换机器部署必须改。

## 四、部署步骤

### 第 1 步：启动数据库与后端

1. 双击 `start_mysql.bat` 启动 MySQL（root / 123456）。
2. 首次跑 `python init_database.py` 初始化数据库，已经初始化过就跳过。
3. 补未来排班，线上预约得有「未来可挂」的号源：
   ```bash
   # 补今天 + 未来 6 天，共 7 天排班
   for /L %d in (0,1,6) do @python demo_prep.py --date %d 2>nul
   ```
   > 我习惯在 PowerShell 里写：
   > ```powershell
   > 0..6 | ForEach-Object { python demo_prep.py --date (Get-Date).AddDays($_).ToString('yyyy-MM-dd') }
   > ```
   > `demo_prep.py` 默认只补「今天」，线上预约得手动把未来几天补上。
4. 双击 `run_web.bat` 启动 Web 服务（默认 `http://127.0.0.1:5000`）。

### 第 2 步：本地调试小程序

1. 下载并安装 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)。
2. 打开工具 →「导入项目」→ 选 `miniapp/` 目录。
3. AppID 选「测试号」，不用注册，直接点就行。
4. 右上角「详情」→「本地设置」→ 勾上「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」。
5. 确认 `app.js` 里 `baseUrl` 是 `http://127.0.0.1:5000`。
6. 编译运行，就能在模拟器里走完「选科室 → 选医生 → 选号源 → 填就诊人 → 挂号」。

### 第 3 步：真机预览（可选）

真机访问不到电脑的 `127.0.0.1`，得做内网穿透：

1. 用 [natapp](https://natapp.cn/) / [ngrok](https://ngrok.com/) / 花生壳之类的工具，把本机 `5000` 端口映射成公网 HTTPS 地址。
2. 把 `app.js` 的 `baseUrl` 改成那个 HTTPS 地址（比如 `https://xxxx.natapp.cc`）。
3. 开发者工具里点「预览」扫码，真机上就能试。

> 如果穿透出来还是 HTTP，真机这边也要继续勾着「不校验合法域名」。

### 第 4 步：真要发布（可选）

我暂时没发，真要上线得做这几件事：
1. 注册微信小程序账号，拿正式 AppID。
2. 后端部署到有公网 IP / 域名的服务器（或云函数），必须 HTTPS。
3. 在「小程序后台 → 开发 → 开发设置 → 服务器域名」里把后端域名加进 request 合法域名。
4. 接入 `openid` 登录（`wx.login` + 后端 `code2Session`），替掉现在用身份证号识别的方式。
5. 数据库迁到公网可访问的云数据库（腾讯云/阿里云 RDS 之类）。

## 五、常见问题

| 现象 | 原因与解决 |
|------|-----------|
| 科室列表为空 | 数据库没启动，或者没有医生归属的科室；先启动 MySQL 再初始化 |
| 排班列表为空 | 未来 7 天没排班，跑 `demo_prep.py --date` 补上 |
| 挂号报「号源已满」 | 这个排班约满了，换个号源或者补排班 |
| 真机请求失败 | 没勾「不校验合法域名」，或 `baseUrl` 不是真机能访问的地址 |
| 报「数据库连接失败」 | Web 服务起来了但 MySQL 没起来，先跑 `start_mysql.bat` |
